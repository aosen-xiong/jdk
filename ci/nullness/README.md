# Namespace nullness CI

This job checks only `javax.xml.namespace` in `java.xml`: `QName.java` and
`NamespaceContext.java`. It uses Checker Framework annotations in JSpecify mode.
`package-info.java` is reviewed documentation, not a checked declaration file.

The annotation decisions are in [contracts.json](contracts.json); declaration
scope and exact source hashes are in [reviews.json](reviews.json). The Javadoc
review preceded annotation edits. `QName` accepts null namespace URIs in both
multi-argument constructors and null in `equals`. Its local names, prefixes and
`valueOf` inputs remain non-null. `NamespaceContext` retains its existing
contracts; only the placement of its existing `@Nullable` changes.

## What runs

The **Namespace nullness (JSpecify)** job runs on pull requests, pushes to master or
`codex/nullness-*` study branches, and manual dispatch. It checks the exact PR head, without workflow-level path
filters or `continue-on-error`.

1. Build CF revision `c12ce38daa5a3978ac3fce693c8f870ebecbd09b` with Temurin
   `21.0.7+6`. Bundle the independent annotated-JDK revision
   `0af1a5ad1f994431fc6e08540000c4ae1ab13153`; disable the Gradle task that would
   update it. Record the actual built JAR hashes and build log.
2. Use Temurin `17.0.14+7` for source checking. Six module probes verify execution,
   opt-in behavior, rejected null returns, annotation locations, assumed purity
   and enabled assertions.
3. Check both enrolled files separately against the current checkout's complete
   `src/java.xml/share/classes` source root, using `--patch-module`, `-proc:only`
   and `-implicit:none`. Binary dependencies use the pinned bundled contracts.
4. Run 19 documented caller/implementation controls. Some deliberately fail
   compilation; each must produce exactly its expected checker diagnostics.
   These include a QName subclass, a NamespaceContext implementation, and
   invalid null arguments, dereferences, return values and iterator elements.
5. Repeat file checking with `-AwarnUnneededSuppressions`.

A scratch removal control demonstrates why body checks alone are insufficient:
removing the two nullable namespace-URI parameters leaves QName's body clean,
but rejects both documented-valid constructor calls. The actual source is never
modified by these controls.

The gate rejects errors, warnings, crashes, timeouts, diagnostic truncation,
missing visitation, stale scope reviews and suppressions. Package inventory is
checked against the explicit manifest: dropping an existing source from the
manifest or adding a new unreviewed package source fails the job. Source hashes
bind manual reviews to exact files; they do not replace semantic review.

Every run retains its explicit input, command, source hash, reviewed scope,
full log, runtime/artifact identities and structured result. The workflow uploads
`.nullness-ci/` even after failure, with 30-day retention. Download evidence that
needs longer retention. No personal skill directory, frozen Mac JAR, token or
secret is required.

## Local reproduction

Check out the two dependency repositories at the exact revisions above. With
the matching JDK installations, run from this repository:

```sh
python3 ci/nullness/bootstrap.py \
  --checker-root /path/to/checker-framework \
  --bundled-jdk-root /path/to/pinned-bundled-jdk \
  --build-java-home /path/to/temurin-21.0.7 \
  --check-java-home /path/to/temurin-17.0.14
python3 -m unittest discover -s ci/nullness -p 'test_*.py'
python3 ci/nullness/run.py preflight --label preflight
python3 ci/nullness/run.py check --label namespace
python3 ci/nullness/namespace_contracts.py --label contracts
python3 ci/nullness/run.py check --audit-suppressions --label suppression-audit
```

`bootstrap.py --local-runtime` explicitly permits another build of Java 21.0.7
and 17.0.14 and labels the generated profile separately. Such a local run is not
the pinned Linux CI result. Bootstrap requires a fresh output directory; archive
the old `.nullness-ci` directory before deliberately rebuilding. Source and
artifact revisions must match the pins, including for local runs.

## Maintaining the package

For each changed file, review source Javadoc and inherited contracts first,
classify documented facts and implementation-derived invariants, then update
its exact source hash and scope record in `reviews.json`. Add meaningful caller
controls when its public contracts change. Do not add a suppression or weaken a
documented non-null guarantee merely to get green CI. Review changes to the
manifest, assumptions, dependency pins and workflow explicitly.

The checker configuration is pinned in `config.json`. Deliberate upgrades need
a new profile and revalidation; neither bootstrap nor CI pulls a floating master.
The runtime profile generated by bootstrap records host paths and actual build
hashes, and is ignored by Git. The Actions revisions are also pinned.

## Limits and upstream readiness

JSpecify mode assumes initialized state, map-key correctness and purity, enables
assertion refinements, and uses permissive defaults for unchecked dependencies.
These are recorded assumptions, not properties proved by this job. Abstract
interface declarations are checked along with controlled implementations; no
module-wide implementation check, native JDK build or JAXP runtime suite is run
by this workflow. Existing repository workflows are unchanged.

Before upstream submission, review existing external implementations and callers.
One source-review follow-up is
`com.sun.org.apache.xerces.internal.util.NamespaceContextWrapper.getNamespaceURI`:
it directly delegates to XNI `NamespaceContext.getURI`, whose contract permits
null for an unbound prefix. The javax interface instead specifies an empty
string. This observation has not been runtime-tested here; it does not justify
weakening the documented javax contract or changing executable code in this PR.

This workflow creates a normal failing/passing PR check. Repository branch
protection and merging remain separate decisions.
